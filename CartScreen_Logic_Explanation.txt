# Cart Screen Address Management Logic Explanation

## Overview
This document explains the logic implemented in the CartScreen.js for managing delivery addresses. The system allows users to select from their saved addresses or add new ones, ensuring a seamless checkout experience.

## 1. Mapping Logic: How Addresses are Fetched and Displayed

### Step 1: State Management Setup
- **addresses**: Array to store all user addresses fetched from the server
- **selectedAddressId**: Tracks which address is currently selected (by ID)
- **deliveryAddress**: String containing the full address text for the selected address
- **showAddNew**: Boolean flag to toggle the "add new address" form
- Additional states for form inputs: newAddress, newAddressType, newAddressName, addingAddress

### Step 2: Data Fetching Process
**Function: fetchAddresses()**
1. Retrieves current user data from AsyncStorage
2. Makes API call to `GET /api/addresses?userId=${currentUser.id}`
3. Receives array of address objects from server
4. Automatically selects default address or first address if none selected
5. Updates local state with fetched addresses

**API Response Structure:**
```javascript
[
  {
    id: 1,
    userId: 123,
    type: "home", // "home", "work", "other"
    name: "Home", // Custom name like "Office", "Mom's Place"
    address: "123 Main St, City, State 12345", // Full address text
    isDefault: true, // Boolean indicating default address
    createdAt: "2024-01-01T00:00:00.000Z",
    updatedAt: "2024-01-01T00:00:00.000Z"
  }
]
```

### Step 3: UI Mapping Process
**Address List Rendering:**
1. Checks if addresses array is empty
2. If empty, displays message: "No addresses saved. Add your first delivery location."
3. If addresses exist, maps each address to a TouchableOpacity component

**Individual Address Component Mapping:**
```javascript
addresses.map((addr) => (
  <TouchableOpacity
    key={addr.id}
    style={[styles.addressOption, selectedAddressId === addr.id && styles.selectedAddress]}
    onPress={() => selectAddress(addr)}
  >
    {/* Address Header: Name and Default Badge */}
    <View style={styles.addressHeader}>
      <Text style={styles.addressName}>{addr.name}</Text>
      {addr.isDefault && <Text style={styles.defaultBadge}>Default</Text>}
    </View>

    {/* Full Address Text */}
    <Text style={styles.addressText}>{addr.address}</Text>

    {/* Address Type */}
    <Text style={styles.addressType}>{addr.type}</Text>
  </TouchableOpacity>
))
```

**Mapping Breakdown:**
- **addr.name** → Display name (e.g., "Home", "Office")
- **addr.address** → Full delivery address text
- **addr.type** → Address category ("home", "work", "other") with CSS text-transform: capitalize
- **addr.isDefault** → Conditional rendering of "Default" badge
- **addr.id** → Used for selection tracking and API operations

### Step 4: Selection Logic
**Function: selectAddress(address)**
1. Updates selectedAddressId to address.id
2. Updates deliveryAddress to address.address
3. Triggers UI re-render to show selected state

**Visual Feedback:**
- Selected address gets green border and light green background
- Unselected addresses have standard white background with light border

## 2. Conversion Logic: How Selected Address Becomes Delivery Address

### Step 1: Address Selection to String Conversion
**Process Flow:**
1. User taps on address option
2. selectAddress() function called with full address object
3. selectedAddressId set to address.id (for UI tracking)
4. deliveryAddress set to address.address (string value for order)

### Step 2: Validation Before Checkout
**Function: handleCheckout()**
```javascript
const handleCheckout = () => {
  if (!selectedAddressId) {
    Alert.alert('Error', 'Please select a delivery address');
    return;
  }
  // ... proceed to payment
};
```

**Validation Logic:**
- Checks if selectedAddressId exists (not null/undefined)
- If no address selected, shows error alert
- If address selected, allows navigation to PaymentScreen

### Step 3: Data Transmission to Order Creation
**Navigation to PaymentScreen:**
```javascript
navigation.navigate('Payment', {
  cartItems,
  deliveryAddress, // String value passed here
  totalAmount: calculateTotal(),
});
```

**Order Creation in PaymentScreen:**
```javascript
const orderPayload = {
  userId: currentUser.id,
  quantity: cartItems.reduce((s, i) => s + i.quantity, 0),
  deliveryAddress, // String from selected address
  paymentMethod: 'cod',
  totalAmount,
  // ... other order data
};
```

### Step 4: Address Addition Logic
**Function: addNewAddress()**
1. Validates form inputs (name and address required)
2. Constructs API payload:
```javascript
{
  userId: currentUser.id,
  type: newAddressType, // "home", "work", "other"
  name: newAddressName, // Custom name
  address: newAddress, // Full address text
  isDefault: addresses.length === 0 // First address becomes default
}
```
3. POST to `/api/addresses` endpoint
4. On success:
   - Add new address to addresses array
   - Set as selected address
   - Update deliveryAddress
   - Hide add form and reset inputs
5. On error: Show alert with failure message

### Step 5: Default Address Logic
**Automatic Selection Rules:**
1. On initial load: Select default address (isDefault: true) or first address
2. On adding first address: Automatically set as default
3. On adding subsequent addresses: Not set as default (preserves existing default)

**Server-side Default Management:**
- When setting isDefault: true, server updates all other user addresses to isDefault: false
- Ensures only one default address per user

## 3. Complete Data Flow Summary

### Forward Flow (Display):
1. Component mounts → fetchAddresses() → API call → addresses[] populated
2. addresses.map() → UI components rendered
3. User selects address → selectAddress() → deliveryAddress updated
4. Checkout validation → deliveryAddress passed to PaymentScreen
5. Order creation → deliveryAddress stored in database

### Backward Flow (Addition):
1. User clicks "Add New Location" → showAddNew = true
2. User fills form → newAddress, newAddressName, newAddressType updated
3. User clicks "Save" → addNewAddress() → API POST
4. Success → addresses[] updated → UI re-renders → address auto-selected

## 4. Error Handling and Edge Cases

### Empty State:
- No addresses: Show "No addresses saved" message + "Add New" button
- Loading state: Show spinner during API calls
- Network errors: Graceful fallbacks with user alerts

### Validation:
- Checkout requires selected address
- Add address requires name and address fields
- API errors handled with user-friendly messages

### State Synchronization:
- Local state kept in sync with server data
- Optimistic UI updates for better UX
- Error recovery with data re-fetch

This implementation ensures users can easily manage multiple delivery addresses while maintaining data integrity and providing a smooth user experience.
